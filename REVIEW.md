# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking if MongoDB is alive, violating the contract ("200 only when MongoDB answers; else 503"). | Terminate or pause MongoDB; `GET /health` still returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command('ping')` inside a try-except block; raises `HTTPException(503, "Database unavailable")` if the ping fails. |
| 2 | `create_employee` (lines 86-90) | Race condition on duplicate `emp_code`. `find_one` followed by `insert_one` is not atomic (TOCTOU). Two concurrent requests with the same `emp_code` both pass and insert duplicates. | Run 2 concurrent `POST /employees` requests with identical `emp_code`; both return 201 Created instead of one 201 and one 409. | Created unique index on `emp_code` at startup (`db.employees.create_index("emp_code", unique=True)`), and wrapped insertion in try-except catching PyMongo `DuplicateKeyError` to return 409. |
| 3 | `create_employee` (line 89) | Stores and returns `created_at` as a Python naive datetime object rather than epoch milliseconds (integer) required by OpenAPI. | Check `created_at` type in `POST /employees` response body; it is a datetime string/object instead of integer ms. | Set `doc["created_at"] = int(datetime.now(timezone.utc).timestamp() * 1000)` (integer epoch ms). |
| 4 | `EmployeeIn` (lines 53-60) | Missing schema validations: accepts invalid time strings for `shift_start`/`shift_end`, permits `shift_start == shift_end`, invalid email format, invalid date string for `joined_on`. | Post employee with `shift_start == "09:30"` and `shift_end == "09:30"`; returns 201 instead of 422 Unprocessable Entity. | Added Pydantic field validators with regex for `HH:MM`, `YYYY-MM-DD`, email format, and model validator ensuring `shift_start != shift_end`. |
| 5 | `list_employees` (line 93) | Off-by-one pagination error: `skip = page * page_size`. For 1-indexed `page=1`, skips `1 * 20 = 20` items, missing the entire first page. | `GET /employees?page=1&page_size=2` returns items starting from index 2 instead of index 0. | Fixed calculation to `skip = (page - 1) * page_size`. Added validation `page >= 1`, `1 <= page_size <= 100`. |
| 6 | `list_employees` (line 94) | `total` count ignores department filter: `total = db.employees.count_documents({})`, violating rule R10 ("total always reflects the filters"). | `GET /employees?department=Engineering` on dataset with 6 employees (2 in Engineering) returns `total: 6` instead of `total: 2`. | Changed count query to `total = db.employees.count_documents(q)`. |
| 7 | `list_employees` (line 95) | Missing sort order: results returned in natural MongoDB order instead of sorted by `emp_code` ascending per OpenAPI. | Create employees out of order; `GET /employees` returns them unsorted. | Added `.sort("emp_code", ASCENDING)` to the MongoDB query. |
| 8 | `punch_in` (line 101) | No check for whether employee exists before reading `emp["shift_start"]`. Non-existent employee causes `TypeError` and unhandled 500. | `POST /attendance/punch-in` with `emp_code: "EMPXXXX"` returns 500 Internal Server Error instead of 404 Not Found. | Added check: `if not emp: raise HTTPException(404, detail="Employee not found")`. |
| 9 | `punch_in` (line 104) | Race condition on single daily punch-in. `find_one` followed by `insert_one` allows concurrent requests to create multiple records for same employee on same day (violates R1). | Run simultaneous punch-in requests for same employee and date; multiple records are inserted. | Created unique compound index on `[("emp_code", ASCENDING), ("date", ASCENDING)]` at startup; catch `DuplicateKeyError` to return 409 Conflict. |
| 10 | `PunchInIn` / `punch_in` (line 66, 109) | Status validation missing. Accepts invalid punch-in statuses like `ABSENT` or `LEAVE` which cannot be punched in via API. | `POST /attendance/punch-in` with `status: "ABSENT"` returns 201 Created instead of 422 Unprocessable Entity. | Validated `status` strictly against allowed punch-in set `{"PRESENT", "WFH", "ON_DUTY"}`; raises 422 otherwise. |
| 11 | `compute_late_minutes` (lines 33-37) | Grace period logic bug (R2). Uses `int((punch_in - start).total_seconds() / 60) > 10`. For punch-in at 09:40:01 (10m 1s), total seconds is 601; `int(601/60)` is 10, so `10 > 10` is False, returning 0 instead of 10. Also disregards timezones (naive replacement). | Punch in at 09:40:01 for 09:30 shift returns `late_minutes = 0` instead of `10`. | Calculated exact difference in seconds: `if diff_seconds > 600: return int(diff_seconds // 60) else: 0`, and normalized datetime to IST timezone. |
| 12 | `compute_work_hours` (line 41) | Uses Python's built-in `round()`, which implements banker's rounding (round-half-to-even) rather than standard half-up rounding (R4, R8). | Work duration of 4.545 hours rounds to 4.54 instead of 4.55. | Implemented helper `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 13 | `compute_overtime` (lines 44-47) | Overtime threshold bug (R3). Returns `max(0, int((punch_out - end).total_seconds() / 60))` without checking if overtime is at least 30 minutes. Also fails on shifts crossing midnight. | Punch out at 18:40 (10 mins after 18:30) returns 10 overtime minutes instead of 0. | Count overtime only if `diff_seconds >= 1800` (30 min); otherwise return 0. Handled overnight shifts where `shift_end < shift_start`. |
| 14 | `list_attendance` (lines 144-150) | In-memory loading & sorting: `docs = list(db.attendance_logs.find(q))` loads all records into Python memory and sorts via `docs.sort()`, causing high memory/OOM and slow queries on 100k docs. Also date inversion (`date_from > date_to`) returns empty list instead of 422. | `GET /attendance?date_from=2026-07-09&date_to=2026-07-01` returns 200 instead of 422; query on 100k records causes memory spike and COLLSCAN. | Added input validation returning 422 when `date_from > date_to`. Delegated sorting, skipping, and limiting to MongoDB with `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)` backed by compound index. |

Also note anything you looked at and decided was **not** a defect, and why:

1. **Use of FastAPI framework and Pydantic models**: Clean, asynchronous ASGI architecture with built-in schema serialization and OpenAPI specification support.
2. **Environment variable loading with python-dotenv**: Correctly reads `MONGO_URI` and `MONGO_DB` from environment or local `.env` with sensible local fallbacks without hardcoded secrets.
3. **Pydantic default shift values (`09:30` and `18:30`)**: Standard corporate shift timings aligned with the assignment problem statement and test fixtures.
